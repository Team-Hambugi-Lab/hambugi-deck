- 장수가 많으니 **한 장에 한 문장**이 기본이다. "(넘김)" 표시된 장은 말없이 넘기거나 짧게만 말한다.
- 말투는 "~했습니다"와 "~했어요"를 섞은 구어체. 외우기보다 흐름만 익혀서 자기 말로 하는 게 자연스럽다.

## 이정연 · 도입과 DE 학습

**1. 표지**
안녕하세요! 저희는 금융 / 엔지니어링 3조입니다.

**2. 팀 햄부기**
팀원은 김태은, 이정연, 진재언 세 명이고요. 팀 이름은 다들 햄버거를 좋아해서 햄부기로 지었습니다. 오른쪽이 저희 팀 로고예요.

**3. 목차** (넘김)

**4. 8주를 한 장으로**
8주를 한 장으로 보면 이렇습니다. 1주차에 데이터 엔지니어링 기초를 같이 공부한 뒤, 2주차부터 4주차는 ICT융합 공모전에 낸 비자부기, 5주차부터 8주차는 빅콘테스트를 준비했어요.

**5. 데이터 엔지니어링 학습** (넘김)

**6. 세 명이 세 파트를 나눠 맡았다**
1주차에는 데이터 엔지니어링 개념을 셋이 나눠서 공부했어요. 태은님이 개론과 파이프라인, 제가 저장과 모델링, 재언님이 오케스트레이션을 맡아서 서로 발표하는 방식이었습니다.

**7. 실제로 만든 1주차 발표 자료**
이게 실제로 만든 자료예요. 태은님은 파이프라인과 ETL, ELT를, 재언님은 Airflow 같은 오케스트레이션 도구를 정리했고, 저는 노션으로 정리해서 발표했어요.

**8. 현업은 왜 이렇게 나눌까**
운영용 DB랑 분석용 DB를 왜 따로 두는지, 정규화는 언제 하는지 같은 기본 개념 위주로 공부했습니다. 처음엔 이론 같았는데, 공모전 하면서 다 다시 나오더라고요.

**9. 배운 개념이 바로 공모전에 쓰였다**
여기서 배운 개념은 뒤에서 그대로 썼어요. 정규화는 ICT융합 공모전에서 비자 네 종류가 같이 쓰는 데이터 구조를 짤 때, 원본 보존은 PDF 대신 한글 파일 원문을 직접 읽을 때 썼고요. 데이터 품질은 빅콘테스트에서 제공받은 데이터 파일 20개를 하나하나 열어서 검증할 때 썼습니다. 비자부기는 태은님이 설명하겠습니다.

## 김태은 · 비자부기

**10. ICT 공모전 · 비자부기** (넘김)
먼저 비자부기입니다.

**11. 충북 외국인 주민을 위한 다국어 AI 행정지원**
충북에 사는 외국인분들이 비자 준비할 때 필요한 정보를 한 번에 볼 수 있게 만든 서비스예요.

**12. 실제로 돌아가는 화면**
홈에서는 준비가 얼마나 됐는지 보이고, 서류 탭에서 신청서를 찍으면 빠진 항목을 알려줍니다.

**13. 시연 영상** (영상 약 30초 재생)
직접 보여드릴게요.
(영상 재생 후) 이렇게 로그인부터 챗봇 상담까지 실제로 돌아갑니다.

**14. 공고 21건을 서비스 데이터로**
이걸 만들려고 비자 공고 21건을 하나하나 뜯어서 데이터로 만들었습니다.

**15. 비자 여러 개가 함께 쓰는 공통 스키마**
비자가 여러 종류라, 공통으로 쓸 수 있는 테이블 구조를 먼저 잡았어요.

**16. 이번 주 일단 뼈저리게 깨달은 점: 공통 스키마**
이건 재언님이 실제로 보고서에 쓴 말이에요. 처음 짠 구조로는 비자마다 다른 조건이 안 담겨서, 결국 다 갈아엎고 다시 설계했습니다.

**17. PDF를 버리고 HWPX 원문으로 갔다**
PDF로 바꾸면 숫자가 날아가서, 그냥 한글 파일을 직접 읽었어요.

**18. 매달 올라오는 공고를 자동으로 반영**
매달 공고가 바뀌면 달라진 부분만 뽑아주고, 최종 반영은 사람이 확인하게 했어요.

**19. 데이터에서 화면까지, 서비스로 연결했다**
이렇게 만든 데이터를 챗봇, 온보딩, 지도 같은 기능에 연결했습니다.

**20. 공고 문장이 통째로 사라졌다**
고생했던 거 두 개만 말씀드리면, 공고 문장 일부가 추출할 때 통째로 사라졌어요. 한글 파일 안에 숨은 공백 기호 때문이었는데, 읽는 방식을 바꿔서 해결했습니다.

**21. 고치다 보니 같은 기관 안내가 갈라졌다**
또 하나는, 같은 기관 정보를 여러 줄에 복사해 뒀더니 하나 고치면 다른 줄이랑 내용이 달라지는 문제였어요. 1주차에 배운 정규화를 진짜로 겪은 셈이죠.

**22. 결과는 탈락. 주제가 흔했나...**
결과는 탈락이었습니다. 이렇게 밤까지 샜는데요. 실제 사용자 반응을 못 보여준 게 컸던 것 같아요. 빅콘테스트는 재언님이 이어가겠습니다.

## 진재언 · 빅콘테스트

**23. 빅콘테스트** (넘김)
다음은 빅콘입니다.

**24. 고립은 스스로 드러나지 않는다**
고립된 분들은 먼저 도움을 요청하지 않으니까, 데이터로 먼저 찾아보자는 게 주제였어요.

**25. 무엇으로 고립을 볼 것인가**
SK 유동인구랑 신한카드 데이터를 받았고, 통계청이나 서울시 자료를 더 붙였습니다.

**26. 명세서를 믿지 않고 원본 20개를 다 열었다**
원본을 열어보니 12월 파일은 두 번 들어가 있고, 카드 데이터는 사람 적은 칸이 지워져 있었어요.

**27. 춘천은 조용히 바뀌고 있었다**
춘천은 전체로 보면 2% 줄었는데, 일부 면 지역은 20% 넘게 줄었더라고요.

**28. 동 평균은 동네 안의 차이를 가린다**
같은 동 안에서도 1인가구 비율이 66%인 곳과 8%인 곳이 섞여 있어서, 더 작은 단위로 쪼개서 봤습니다.

**29. 두 개의 신호를 교차한다**
그래서 두 가지를 봤어요. 어디가 위험한 동네인지, 그리고 실제로 덜 움직이는 사람이 어디 있는지.

**30. 어디가 위험한가: 고립 위험 지수** (넘김)

**31. 고립 위험 지수: 두 테마, 여섯 지표**
먼저 위험한 동네는, 혼자 사는 어르신이 많은 곳과 주거가 불안정한 중장년이 많은 곳, 이 두 기준으로 점수를 매겼어요.

**32. 누가 줄었나: 활동 저하 신호** (넘김)

**33. 기대보다 덜 움직이는 동네를 찾는다**
그리고 원래 이 정도는 움직여야 하는데 계속 덜 움직이는 곳을 찾았더니, 60대 이상 기준으로 461곳이 나왔습니다.

**34. 만든 지표가 현실과 맞는가**
실제로 맞는지 서울시 자료랑 비교해 봤는데, 신호가 많은 동일수록 어르신들이 집에 오래 머물고 덜 움직였어요.

**35. 두 신호를 교차해 다섯 유형으로**
두 신호가 다 걸리는 곳은 157곳이었습니다.

**36. 관찰하고, 판단하고, 연결하는 에이전트**
이 결과를 바탕으로, 대화하면서 상태를 확인하고 맞는 복지기관을 연결해 주는 에이전트를 설계했습니다.

**37. 대화로 확인할 24개 위험 특징** (넘김)

**38. 29세, 역삼1동, 1인가구**
예를 들어 이분이 "사라지고 싶다"고 하면, 그때는 바로 사람한테 연결되게 했어요.

**39. 상업지가 최고 위험으로 나왔다**
제일 오래 붙잡고 있던 문제는, 처음 지수를 지도에 올렸더니 테헤란로 같은 사무실 동네가 제일 위험하게 나온 거였어요. 그걸 고치니까 이번엔 강남 1인가구 3만 가구가 아예 판단에서 빠져버렸고요.

**40. 보류를 쪼개고, 테마를 나눴다**
그래서 판단을 미루는 기준을 세 단계로 나눠서 빠지는 곳을 291곳에서 70곳 정도로 줄였습니다.

**41. 마지막 일주일**
마지막 일주일은 정말 몰아쳤고, 마감 59분 전인 밤 11시 1분에 냈습니다.

**42. 집계구 기반 사회적 고립 조기 탐지 및 지속 관리** (넘김)

## 리허설 메모

- 시연 영상은 30초 안팎으로 잘라서 준비한다. 전체 영상(3분 15초)을 틀면 8분을 넘긴다.
- "(넘김)" 장은 1~2초 안에 넘긴다. 여기서 시간을 아끼는 게 제일 크다.
- 시간이 넘치면 줄일 순서: 8번, 27번, 35번 생략, 18번과 19번을 한 문장으로 합치기
- 숫자는 말하기 쉬운 것만 말한다. 나머지는 슬라이드로 보여주기만 한다.
- 48번 회고 문장은 각자 주차 보고서에서 뽑은 것. 슬라이드에도 같은 문장이 들어가 있다.
- 발표자를 바꾸면 9번, 22번, 42번 끝의 연결 멘트도 같이 바꾼다.
